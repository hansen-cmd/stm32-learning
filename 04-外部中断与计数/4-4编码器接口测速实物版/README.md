# 4-4 编码器测速（硬件 vs 软件对照诊断版）
> 同屏对比 TIM3 硬件编码器接口与软件正交解码的计数结果，用来定位「编码器读数不对」到底是谁的锅。这是本仓库注释最详细、最有排查价值的一个程序。

---

## 学什么

- **TIM3 编码器接口模式**：定时器硬件自动完成正交解码，不占用 CPU，快速转动也不漏步
- `TIM_EncoderMode_TI12` —— 同时计数 A、B 两相的上升沿和下降沿（4 倍频）
- **查表法软件解码**：`(上一状态<<2)|当前状态` 作索引查 `QTABLE`，非法跳变（抖动）对应 0，天然抗抖
- 对照诊断思路：同一路信号用两种方式各解一次，谁对谁错一目了然

## 硬件连接

编码器 A、B 相 → PA6、PA7（TIM3 的 CH1/CH2）

## 关键代码

屏幕四行含义：

| 行 | 内容 | 说明 |
|:--:|---|---|
| 1 | `HW` | **硬件**编码器接口计数（TIM3 CNT） |
| 2 | `SW` | **软件**查表解码计数 |
| 3 | `AB x y` | PA6、PA7 的实时电平（0/1） |
| 4 | `dH dS` | 每 200ms 内两者的变化量 |

**怎么判读：**
- `SW` 大幅变化、`HW` 只在 0/1 跳 → 信号没问题，是 TIM3 硬件编码器没配好，先用软件解码
- 两者都大幅变化 → 硬件软件都正常，之前是显示/采样的误解
- 两者都不动 → 查接线、供电、信号线

## 注意与踩坑

- 这是我排查「旋转时 CNT 只在 0/1 跳、SPD 最大到 5」时写的诊断程序，注释写得很详细，**遇到问题值得回来读一遍**
- 第 3 行的 `AB` 电平显示能快速验证「信号到底有没有到引脚」，排查硬件问题的第一刀
